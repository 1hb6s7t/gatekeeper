  • 读者先发现矛盾，作者后知后觉；人工维护设定集成本高、也查不全

为什么是这个方向

三个理由

失败点收敛

欧美写作工具、中文网文平台、短剧编剧工具、学术长文基准，共同短板都是长篇一致性；其余环节已很卷。

合规上敞开的门

平台普遍允许 AI 辅助检查、明确禁止 AI 代写正文。检查是唯一既不越界、又真刚需的切口。

可量化

能造答案卡：预埋矛盾 + 不该报的陷阱，产出召回率、误报数、引用命中率，而不是「看起来不错」。

可交付

prompt 哈希缓存让评审不配密钥也能走通全路径；真实通道另有完整评测日志。

关键选择

四个取舍

  • 只做检查，不做生成
    边界划死：不写正文、不改文风，只回答「哪里对不上」
  • 证据校验交给程序，不交给模型
    引用必须逐字出现在原文，对不上就在界面标黄
  • 「有意为之」做成结构化规则
    服务端按实体名 + 文本做可解释匹配，下次检查自动折叠，不依赖模型自觉
  • 离线也要能演示
    模型原始输出按 prompt 哈希缓存进仓库，无密钥秒级走通全流程

AI 如何参与开发

产品里是引擎，研发中是结对

产品侧

AI 是被调用的检查引擎：抽取设定、比对矛盾。三条通道可切换（OpenAI 兼容 / Anthropic SDK / claude -p）。

研发侧

全程 AI 编程代理结对：市场调研 → 写实施方案 → 拆成 7 个任务逐个推进 → 真实评测与收尾；十余次独立提交，可逐条回看。

它也暴露了自己的问题

网关带隐藏推理 token → 输出被截断 → 加自动重试；模型给引用包引号 → 逐字校验误判 → 校验逻辑做引号归一化。

分工

人负责判断、取舍与验收；AI 负责调研、执行与试错。每一个结论都由程序和答案卡复核。
