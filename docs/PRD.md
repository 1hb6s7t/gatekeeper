# 守门人 Gatekeeper — 一页 PRD

日期：2026-09-09 · 时间盒：5 小时 · 一人

## 目标用户
连载中的中文长篇小说作者（网文日更作者为主），已写 5 章以上，正在写下一章。

## 要解决的一个问题
写到几十章之后，作者自己也记不清前文设定：人物眼睛颜色、谁认识谁、某物件在谁手里、事情发生在第几天。现有 AI 写作工具在这里失败：Sudowrite 把静态设定全量塞进 prompt，冲突时不报错只缝合；Novelcrafter 要作者手工维护 Codex。平台规则（番茄、起点、七猫、晋江）允许 AI 做大纲、人设、检查，禁止 AI 代写正文。

## 产品判断
AI 不动笔。它只做三件事：从已写章节里**抽取**设定与时间线、对新章节**找矛盾**、每条结论**附原文证据**。作者决定采纳、忽略，或标记「有意为之」（伏笔）。

## 唯一必须走通的用户路径
1. 粘贴已写章节（自动按「第 N 章」切分）
2. 一键「建立设定库」：角色、地点、物品、时间线，每条事实带来源章节和原文引用
3. 粘贴新章 → 「检查」：矛盾清单，每条含类型、严重度、设定来源引用、新章冲突引用、修改建议
4. 对每条：采纳 / 忽略 / 标记有意为之（下次不再报）
5. 内置示例作品（5 章 + 预埋 10 处矛盾的第 6 章）+ 答案卡，一键跑评估看召回与误报

## 范围外（明确不做）
正文生成、文风模仿、去 AI 味、大纲生成、多用户、账号系统、数据库。

## 真实 / 缓存 / 未完成
- 真实：切章、抽取、检查、证据定位、采纳与「有意为之」记忆、评估脚本，均为真实调用模型（Anthropic SDK 或 `claude -p` 两条通道，可切换）
- 缓存：内置示例的抽取与检查结果预先生成并随仓库分发，无 API 也能完整体验；界面明确标注「缓存结果」
- 未完成：见 README「下一步」

## 成功标准
内置示例的 10 处预埋矛盾中召回 ≥ 7，误报 ≤ 3；一次检查在 60 秒内返回；不依赖网络也能走完路径。
